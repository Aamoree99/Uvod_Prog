# Úvod do programování

Учебные упражнения для группы. Чешские условия и существующие Rust-решения сохранены вместе с комментариями. В заданиях 01–02 и 03_01–03_03 есть русские пояснения к алгоритмам. Готовые упражнения переведены на C#, C++ и Java: по 35 самостоятельных программ, включая `zapocet_E`. Rust-оригиналы сохранены без изменений.

## Структура

```text
uvod/
├── rust/                 # Cargo.toml, Cargo.lock, src/main.rs, src/bin/<задача>/main.rs
├── csharp/               # src/exercises/<задача>/Program.cs + Exercise.csproj
├── cpp/                  # CMakeLists.txt, src/exercises/<задача>/main.cpp
├── java/                 # src/main/java/exercises/task_<задача>/Main.java
├── zapocet/              # Общие материалы тестов и ссылки на решения
├── UPg_cviceni.txt       # Условия курса
└── .vscode/settings.json # rust-analyzer использует rust/Cargo.toml
```

Все 77 заданий из папок 01–12 находятся в `rust/src/bin/`: например, задача 3.6 — `03_06/main.rs`. У 43 заданий пока есть только условие и минимальная точка входа с сообщением об отсутствии решения. Это позволяет собрать проект целиком, не выдавая заглушки за решения.

## Rust: запуск и сборка

Нужен Rust с поддержкой edition 2024. Из корня репозитория:

```sh
cd rust
cargo check
cargo build
cargo run --bin 03_05
cargo run --bin 03_06
cargo run --bin zapocet_E
```

Все зависимости, включая `rand`, находятся в `rust/Cargo.toml`. Запускайте упражнения через Cargo.

Последовательный запуск всех задач:

```sh
cd rust
cargo run
```

Запускатель сортирует каталоги `src/bin/`, показывает название из условия и запускает каждую задачу через Cargo. Интерактивный ввод остаётся в терминале. При ошибке сборки выводит `COMPILE ERROR` и останавливается; при неуспешном завершении задачи — `RUNTIME ERROR` и продолжает.

Откройте корень `uvod` в VS Code: общая настройка rust-analyzer указывает на Cargo-проект. Сборки и локальные файлы исключены через `.gitignore`; `Cargo.lock` сохраняется в Git.

## C#, C++ и Java: отдельные упражнения

Переведены `01_01`–`01_11`, `02_01`–`02_10`, `03_01`–`03_08`, `04_01`–`04_05` и `zapocet_E`. Задания с Rust-заглушками не переводились. В каждом файле сохранено чешское условие и добавлены русские пояснения к алгоритму. Общие точки входа этих трёх языков пока остаются каркасами; запускайте отдельные упражнения.

Команды из корня репозитория:

```sh
# C#: .NET SDK 8 или новее, отдельный проект для каждой задачи.
dotnet run --project csharp/src/exercises/03_06/Exercise.csproj

# C++: C++17; CMake создаёт отдельную цель для каждого упражнения.
cmake -S cpp -B cpp/build
cmake --build cpp/build --target 03_06
./cpp/build/03_06

# Java: JDK 17 или новее; все классы имеют разные пакеты.
mkdir -p java/build
javac -encoding UTF-8 -d java/build java/src/main/java/exercises/task_03_06/Main.java
java -cp java/build exercises.task_03_06.Main
```

В Java префикс `task_` нужен, поскольку имя пакета не может начинаться с цифры. В C# и Java факториал вычисляется через стандартный `BigInteger`, в C++ — массивом десятичных цифр; предел 34 из Rust-примера сохранён. При округлении используется правило Rust: половины округляются от нуля.

## Особенности существующих решений

В [`02_06`](rust/src/bin/02_06/main.rs) сохранено авторское решето Эратосфена до 100000: оно эффективнее простого перебора делителей до 1000 из условия, но использует `Vec` и выходит за ограничения задания. Это расширенный вариант для изучения.

Программы с `unwrap()` предполагают корректный ввод. В [`02_05`](rust/src/bin/02_05/main.rs) алгоритм НОК рассчитан на положительные числа. В [`02_09`](rust/src/bin/02_09/main.rs) числа вводятся по одному на строке; неположительное число завершает последовательность и не входит в неё.

## Тест на оценку 3

По информации автора, на тесте было задание **найти второе максимальное число в массиве**. Учебное Rust-решение — [`zapocet_E`](rust/src/bin/zapocet_E/main.rs); общие материалы — в [`zapocet/`](zapocet/README.md).

Идея: за один проход храним два максимума. Новый лидер сдвигает старый максимум на второе место; иначе число может улучшить только второе место. Порядок присваиваний важен. Сортировка не нужна.

В решении повторы учитываются: `[9, 9, 5]` → `9`. Если условие требует второе **различное** значение, здесь ответ должен быть `5`, а для `[9, 9]` ответа нет. Полное условие теста отсутствует, поэтому правила для повторов нужно сверять с преподавателем.

| К чему готовиться | Похожие цвички |
| --- | --- |
| Обновление максимума | [`01_04`](rust/src/bin/01_04/main.rs) |
| Второе наибольшее из трёх | [`01_05`](rust/src/bin/01_05/main.rs) |
| Сравнения и обмен значений | [`02_01`](rust/src/bin/02_01/main.rs), [`02_02`](rust/src/bin/02_02/main.rs) |
| Два максимума за один проход | [`02_09`](rust/src/bin/02_09/main.rs) — самое близкое среди 01–03 |
| Параметры и возвращаемые значения функций | [`03_01`](rust/src/bin/03_01/main.rs)–[`03_03`](rust/src/bin/03_03/main.rs) |
| Максимумы именно в массиве | Условие [`04_05`](rust/src/bin/04_05/main.rs) — прямое совпадение по принципу |

Потренируйте проход массива по индексу через `while`, отрицательные числа, повторы, массивы длины 0–1 и разный порядок элементов. Сходство цвичек не гарантирует содержание следующих тестов.
