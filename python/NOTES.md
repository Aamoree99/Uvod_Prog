# Перенос и проверка Python

Python 3.11+, стандартная библиотека, без внешних зависимостей.
Представлены все 78 Rust-заданий: 55 решений (01–07 и `zapocet_E`)
и 23 заглушки (08–12). Чешские заголовки сохранены полностью, включая ограничения
и примеры; автоматическая проверка сравнивает их с текущими Rust-исходниками.
Существующие реализации других языков при этом переносе не изменялись.

## Представление данных

- Массивы представлены списками фиксированной длины. `dict`, `set` и готовые
  сортировки в решениях не используются; алгоритмы выполняются индексными циклами.
- Структуры комплексного числа, точки, даты, дроби и длинного вещественного числа
  представлены кортежами; функции возвращают результаты вместо Rust `&mut`.
- 07_01 и 07_03 используют 100 цифр, 07_05 — 128 цифр, big endian.
  Переносы, заём, умножение в столбик, деление с остатком, НОД и перевод оснований
  выполняются над цифрами; преобразования всего числа во встроенный `int` нет.
- 07_02 использует 40 значащих цифр, little endian, отдельные знак и показатель.
  Лишние значащие цифры отбрасываются, как в Rust. `float`, `Decimal`, `Fraction`
  не заменяют длинную арифметику. `Decimal` применяется только в тестах как оракул.
- 06_01 сканирует исходную строку по индексам. Копируется только возвращаемое слово:
  обычный Python `str` не поддерживает строковый срез-ссылку, аналогичный Rust `&str`.
- 06_02 сдвигает кодовые единицы UTF-16 по модулю 65536, включая пробелы и цифры.
  Это поведение исходной задачи, а не шифр только для букв алфавита.
- Бенчмарки 05_04 и 05_06 используют размеры 1000, 10000 и 30000.
  Для каждого размера все алгоритмы получают копии одного случайного массива.
  Генерация, копирование, проверка результата и запуск интерпретатора не входят
  в замер `time.perf_counter()`. Измеряются алгоритм и его счётчики операций.

## Исправления относительно Rust

Ошибки 02_05, 03_05, 03_08, 04_04 и 07_02 воспроизведены на исходном Rust-коде.

| Задание | Rust | Python |
|---|---|---|
| 02_05 | Деление по модулю на ноль вызывает panic; для -21 и 30 получается -210 | НОК с нулём равен 0; отрицательные аргументы приводятся к положительным |
| 03_05 | Три совпавшие точки считаются прямоугольным треугольником | Сначала проверяется невырожденность |
| 03_08 | 01.01.1899 ошибочно считается понедельником | Учитываются годы до опорного 1900; результат — Sunday |
| 04_04 | Пустой массив вызывает переполнение при `len() - 1` в Debug | Пустой массив обрабатывается без изменений |
| 06_04 | `odd quit` поглощает команду как неверную сумму | `quit` в позиции суммы тоже завершает игру и отменяет ставки |
| 07_02 | `1e100 + (-1)` даёт `1e100`: теряется заём от отброшенных младших цифр | Результат содержит 40 девяток с научным показателем 99 |

Дополнительно игра 03_06 завершается при EOF, вместо бесконечного запроса хода.
Анимация, очистка экрана и задержки Rust-игры не перенесены; правила, счёт до двух
побед и повтор игры сохранены. Округление 04_03 выполняется от нуля на половинах,
как Rust `.round()`, а не встроенным Python `round()` с округлением к чётному.
Вывод `zapocet_E` переведён на английский; повторяющиеся максимумы учитываются.

В условиях найдены опечатки, оригинальный текст не исправлялся:

- 06_04: при результате 24 первая комбинация ставок даёт `100 + 200 - 20 - 25 - 30 = 225`, а не 222.
- 07_02: `-25.62` больше `-9.53407256e18`, поэтому Compare возвращает 1, а не -1.
- 03_03: ряд для `e^5.14` даёт примерно 170.715768; вывод до трёх знаков — 170.716.

Случайные результаты Sportka, игр и времена бенчмарков между языками различаются.
Случайное значение `-74030` из примера Sportka не является обязательным результатом.

## Проверки

Проверено на Python 3.11.17:

- Синтаксис всех файлов; совпадение 78 чешских заголовков с Rust.
- Запуск всех 55 реализованных программ, включая оба полных бенчмарка
  до 30000 элементов, интерактивные программы с вводом и все 23 заглушки.
  Заглушки не засчитываются как проверенные алгоритмы.
- 12 групп автоматических тестов: примеры условий, краевые случаи, сортировки,
  поиск, строки, игры, длинная арифметика, дроби, все римские числа 1–3999.
- Runner: `--help`, `--list`, `--bin`, `--from`, неизвестные номера,
  несовместимые аргументы, сортировка номеров, статистика ошибок и заглушек,
  запуск из другой директории. Рулетка проверена через runner с `quit`.
- Счётчики 05_03 и 05_07 совпадают с Rust на одинаковых массивах.

Повторить автоматические проверки из `python/`:

```bash
python3 -m compileall -q .
python3 -m unittest discover -s tests -v
```

Rust: `cargo build --bins` прошёл без предупреждений; список runner и запуск
05_04 с автоматическим Release и `--from 05_01` (40 запусков без ошибок)
проверены. Полный Rust runner завершил все 78 файлов с нулём ошибок
(23 из этих запусков — заглушки); прямой `cargo run --bin 03_06` тоже проверен. C++: CMake Unix Makefiles,
сборка и интерактивный запуск `build/03_06`, сборка `uvod_cpp` и запуск
`build/03_07` проверены. .NET SDK отсутствует; `java`/`javac` — системные
заглушки macOS без JDK. Команды C# и Java сверены с проектами и пакетами,
но выполнение не проверено. Python 3.11 и CMake для проверок размещены
во временных каталогах; внешние зависимости в репозиторий не добавлялись.
